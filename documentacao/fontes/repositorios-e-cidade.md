## Limites e achados

- Listagens da API Contents são limitadas: a raiz do mirror CPD e `ecidade/` DBSeller chegaram a 1.000 entradas. Ausência nessas listagens não comprova inexistência. Não foi realizada leitura exaustiva dessas árvores.
- READMEs vazios em online/transparencia; finalidade inferida da árvore é hipótese, não contrato funcional.
- O hub descreve Sertão Digital/CPD como preparação de mirrors em partes de `docs/ecosystem.md`; o registro `mirrors/mirrors.json` e os avisos atuais confirmam destinos existentes. Manter data e contexto, sem apagar a história.
- Contass INSTALL aponta para o hub atual como se fosse código e contém instruções administrativas sensíveis. Não reproduzir esse roteiro como receita universal.
- README 2018 aponta para `e-cidade-database`, enquanto o repositório encontrado é `database`; o segundo comando de download repete o destino do schema para os dados. Revisar antes de usar; não sobrescrever schema.
- DBSeller/Sertão Digital README e Compose diferem sobre o volume da aplicação: Compose usa `./ecidade`. O Compose também requer revisão de persistência, autenticação e healthcheck. Leitura estática não comprova instalação funcional.
- O catálogo de módulos descreve possibilidades; não comprova que todas estejam instaladas ou disponíveis em cada fork.
- As datas são do commit consultado, não garantia de manutenção atual nem data de sincronização efetiva com upstream.
