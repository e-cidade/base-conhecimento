# Padrões para documentação e contribuições

**Proposta para revisão comunitária.** Não impõe convenções novas ao código de outros repositórios.

- Português brasileiro, nomes técnicos preservados, caminhos e comandos com contexto.
- Markdown com títulos hierárquicos, links relativos internos e URLs por commit para evidências externas.
- Classificação explícita: verificado por leitura/teste, hipótese, proposta e pendente.
- Mudanças focadas; commit recomendado: docs: assunto, fix: correção, feat: capacidade ou chore: manutenção. Respeitar regras mais específicas do projeto alvo.
- Fonte, autoria e licença antes de reutilizar conteúdo. Prefira síntese própria e ponteiros.
- Exemplos sintéticos e revisão de segredos; nunca tratar valores de demonstração como produção.
- Para código, conservar encoding, estilo e compatibilidade da distribuição; não aplicar um formatter global ao legado sem escopo específico.

Checklist de revisão: versão correta, evidência suficiente, links válidos, consequência operacional clara, ausência de duplicação e validação proporcional. Guia: [contribuição](../governanca/contribuicao.md).
